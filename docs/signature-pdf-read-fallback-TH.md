# BHS E-Document — ผอ.เปิด PDF เพื่อเซ็นไม่ได้หลังเปิดการป้องกัน Backup

## สาเหตุ
`src/PdfSignatureEditor.jsx` เคยเรียก Google Apps Script `action:getFile` โดยไม่ส่งรหัส แต่ระบบ Backup จำกัด endpoint นี้ด้วย `BHS_BACKUP_SECRET`. บัญชี ผอ. ไม่ควรจำเป็นต้องมีรหัส Backup แอดมิน. การยกเลิกการตรวจรหัสที่ Google Apps Script จะเผยไฟล์ราชการให้ผู้ที่ทราบ Drive ID จึงไม่ทำ.

## การแก้
- คงเส้นทางเปิด PDF ผ่าน GAS ที่มีการป้องกันเดิมไว้ เมื่ออ่านไม่ได้ จะมีทางเลือกสำรองให้ผู้ใช้เปิดไฟล์ต้นฉบับใน Drive เพื่อดาวน์โหลด และเลือกไฟล์ PDF ในเครื่องมาเซ็น
- ทดสอบ header/ขนาด/นามสกุล PDF และเตือนผู้ใช้เมื่อชื่อ PDF ไม่ตรงกับชื่อไฟล์ในทะเบียน
- หลังเปิดไฟล์ได้ รองรับ Apple Pencil/เมาส์/ภาพลายเซ็นและบันทึก PDF ฉบับลงนามตามขั้นตอนเดิม
- ห้ามอ่านไฟล์ใดโดยใช้รหัส Backup ในหน้า ผอ. และไม่ส่งรหัสออกไปใน source code.
- ไม่แก้โค้ด GAS, Firebase, Backup, สิทธิ์ผู้ใช้, การอนุมัติ, การออกเลข หรือไฟล์ต้นฉบับใน Drive.
- ยังต้องทดลองลงนามจริงกับไฟล์ทดลองของโรงเรียนบนคอมและ iPad. คำสั่งตัวจริงควรตรวจว่าฉบับลงนามตรงกับต้นฉบับก่อนกดอนุมัติ.
