# BHS E-Document — ลงนาม PDF อัตโนมัติและแก้ปัญหาหน้าเว็บล่ม

## อะไรเปลี่ยนบ้าง
- ผอ. กด “ลงนาม / อนุมัติ” → หน้าเซ็นพยายามดึง PDF จาก endpoint `/api/signing-pdf` อัตโนมัติและแสดงหน้าแรกทันที ไม่ต้องกดโหลดและเลือกไฟล์เอง หากเซิร์ฟเวอร์พร้อมใช้งาน
- ฝั่งเซิร์ฟเวอร์ตรวจเซสชันลงนามแบบ HttpOnly/Secure/SameSite, ข้อมูลผู้ใช้จริงใน Firestore, บทบาท ผอ. / แอดมิน, สถานะ “รอผู้อำนวยการ” และ Drive ID ที่เป็นไฟล์ PDF แนบอยู่กับเอกสารนั้น ก่อนอ่าน PDF ผ่าน GAS ด้วยรหัส Backup ที่เก็บใน Vercel เท่านั้น
- หากยังไม่ตั้งค่าเซิร์ฟเวอร์, เซสชันหมดอายุ, ไฟล์ใหญ่เกิน 4 MB สำหรับ Vercel Function หรือ GAS อ่านไฟล์ไม่ได้ ระบบคงปุ่มเปิด Drive และเลือก PDF ต้นฉบับจากเครื่องเป็นทางสำรองตามเดิม
- PDF แสดงทีละหน้าและจำกัด Canvas ราว 1.4 ล้านพิกเซล เพื่อไม่ให้ใช้หน่วยความจำสูงเมื่อมีหลายหน้า; ใช้ Apple Pencil/เมาส์โดยวาดเส้นบน Canvas โดยตรง แล้วค่อยอัปเดต React เมื่อจบเส้น
- รูปลายเซ็นต้องไม่เกิน 6 MB และถูกย่อเหลือด้านยาวไม่เกิน 1024px ก่อนวาง; คงการบันทึก PDF ลงนาม, ย้อนกลับ, เซ็นหลายหน้า และขั้นตอนอนุมัติเดิม

## ต้องตั้งค่าที่ Vercel ก่อนใช้ระบบเปิด PDF อัตโนมัติจริง
เปิด Vercel → Project bhs-edocument → Settings → Environment Variables แล้วใส่:
1. `BHS_FIREBASE_SERVICE_ACCOUNT_JSON`: JSON Service account ของ Firebase โปรเจ็กต์ `bhs-edoc-2` (ใช้สิทธิ์เท่าที่จำเป็น, เก็บเป็นความลับ)
2. `BHS_SIGNING_SESSION_SECRET`: สตริงสุ่มยาวอย่างน้อย 32 ตัวอักษร ใช้ลงลายมือชื่อเซสชัน
3. `BHS_BACKUP_SECRET`: รหัสสำรองข้อมูล Drive ที่ตั้งใน Google Apps Script **ค่าเดิม** เก็บฝั่งเซิร์ฟเวอร์เท่านั้น อย่าส่งรหัสนี้ผ่านแชต/ใส่ GitHub
4. `BHS_GAS_WEB_APP_URL`: URL `https://script.google.com/macros/s/.../exec` ของ GAS ที่ใช้งานจริง

ต้องกำหนดตัวแปรอย่างน้อยสำหรับ Production และสั่ง Redeploy. หากยังไม่ตั้งค่า เว็บไซต์ยังเข้าระบบได้ตามเดิม และการลงนามจะ fallback มาเลือก PDF จากเครื่อง (ระบบไม่ส่งรหัส Backup ไป browser)

**ความปลอดภัยก่อนใช้งานจริง:** ระบบ login ปัจจุบันยังใช้รหัสผ่านแบบเดิมใน Firestore และมีค่าเริ่มต้น `123456` — API นี้เป็นชั้นป้องกันสำหรับอ่าน PDF เพิ่มเติม แต่ไม่ทำให้ระบบ login หรือ Firestore Rules เดิมปลอดภัยทั้งหมด ควรเปลี่ยนเป็น Firebase Auth + Rules ฝั่งเซิร์ฟเวอร์ และไม่ใช้รหัสผ่านเริ่มต้นสำหรับบัญชี ผอ./แอดมิน. จำกัดสิทธิ์ Google Drive ของไฟล์ราชการตามนโยบายจริงด้วย

## ทดสอบก่อนใช้งานจริง
1. เปิดคำสั่งทดสอบด้วยบัญชี ผอ. ผ่าน Chrome/iPad; กด “ลงนาม / อนุมัติ” แล้ว PDF ต้องเปิดอัตโนมัติ หาก server variables พร้อม
2. ลอง PDF 1, 5, 20 หน้า เปลี่ยนหน้า ไปกลับ เขียนด้วย Apple Pencil และแทรกรูปความละเอียดสูง
3. บันทึกและอนุมัติด้วยไฟล์ทดลอง แล้วเปิดไฟล์ฉบับลงนามในรายละเอียด ตรวจตำแหน่งลายเซ็นและสถานะเผยแพร่
4. ปิดเซสชัน/เปลี่ยนบัญชี แล้วตรวจว่าไม่สามารถอ่าน PDF ผ่าน API ได้
5. หาก PDF ใหญ่เกิน 4 MB ตรวจว่าเห็นทางเลือกดาวน์โหลด+เลือกไฟล์แทน ไม่เกิดหน้าเว็บล่ม

## ขอบเขต
ไม่แก้ Google Apps Script/Firebase Rules/ฐานข้อมูลเดิม/Backup, ไม่เปลี่ยนการเกษียณหรือการเผยแพร่, ไม่เกี่ยวกับเมนูหนังสือภายในที่ยังอยู่ระหว่างถาม–ตอบ (แบบ A).
