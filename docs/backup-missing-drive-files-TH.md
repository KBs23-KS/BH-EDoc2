# สำรองข้อมูลกรณีอ้างอิงไฟล์ Drive ที่ลบไปแล้ว

ปัญหา: Firestore ยังมี field `driveId` ของไฟล์เก่าที่ถูกลบ/ย้ายจากโฟลเดอร์. Backup ไม่ควรลบ Firestore records หรือไฟล์อื่นตาม.

การแก้ไข:
- สำรอง 8 collections ใน Firestore เหมือนเดิม ไม่เขียนหรือลบฐานข้อมูลเดิม
- พยายามดึงทุกไฟล์แนบ; เฉพาะกรณี `ไฟล์ไม่ได้อยู่ในโฟลเดอร์`, `File not found` หรือ Drive ระบุไม่พบ ID จึงบันทึกใน `missingFiles` แล้วทำไฟล์ต่อไป
- รหัสผ่านผิด, ติดต่อ Google Apps Script ไม่ได้ หรือข้อมูล base64 เสีย: **ต้องหยุด** ไม่สร้าง ZIP ที่แอบขาดไฟล์
- ZIP ที่ขาดไฟล์ตั้งชื่อ `BHS-PARTIAL-BACKUP-...` และมี `READ-ME-FIRST.txt`, `MISSING-DRIVE-FILES.json`; ไฟล์ `manifest.json` มี `integrity.status="incomplete"` และชื่อเอกสารที่อ้างอิง
- **บล็อก Restore อัตโนมัติจาก ZIP ที่ไม่ครบ** ทั้งจาก UI และภายในฟังก์ชัน restore เพื่อป้องกันการเขียนทับฐานข้อมูลด้วยสำเนาไม่ครบ
- รายงานในหน้าแอดมินว่าได้ไฟล์แนบกี่ไฟล์ ขาดกี่ไฟล์ และแสดงชื่อที่ขาด
- ไม่แก้ Google Apps Script, ไม่แก้ Firestore Rules, ไม่แตะ PR #5

การได้ไฟล์ ZIP แบบ PARTIAL ช่วยเก็บข้อมูลที่ยังเหลือ แต่ไม่ใช่สำเนาระบบครบชุดหรือรับประกันว่ากู้คืนได้ทั้งระบบ. ต้องตรวจ `manifest.json` และจำนวนไฟล์จริงก่อนนำ PR #5 ขึ้น Production.
