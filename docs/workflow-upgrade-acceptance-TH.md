# BHS E-Document — แผนตรวจรับการอัปเกรด Workflow (29 ต.ค. 2569)

> สาขา feature/edoc-workflow-modern-20261029 / PR #5 เป็นสาขา **ทดสอบ** ห้ามนำขึ้น Production ก่อนผ่านการตรวจสิทธิ์จริงและสำรองข้อมูล

## ข้อกำหนดที่ตกลงแล้ว
- A1: ผอ. ส่งถึงหลายกลุ่ม/กลุ่มสาระและหลายบุคคลได้พร้อมกัน (ไม่ได้บังคับส่งหลายกลุ่ม)
- A2: คนที่อยู่หลายกลุ่มได้รับการเผยแพร่เพียงหนึ่งรายการต่อหนังสือ ไม่สร้างผู้รับซ้ำ
- A4: หัวหน้ารับทราบแล้วจบโดยไม่มอบหมายต่อได้
- A5: เลือกหัวหน้ากับผู้รักษาการรายกลุ่ม มีสิทธิ์ดำเนินการต่อ
- A6: เปลี่ยนผู้รับมอบหมายโดยเก็บประวัติเดิมและแจ้งผู้รับใหม่
- B1/B2/B3/B5: ดูเอกสาร/ตัวอย่าง PDF ในหน้าเว็บ, Timeline, แยกการรับทราบหนังสือออกจากการรับทราบงาน, ค้นหาเอกสาร
- C1–C6: ไอคอนสี, เครื่องมือเพิ่มเติมในเมนูเลื่อนเดียวกัน, ตาราง/แบบฟอร์มมาตรฐานเดียวกัน, มือถือแสดงทะเบียนแบบการ์ด, Dashboard ตามบทบาท
- D1–D6: ร่างแบบฟอร์มข้อความ (อุปกรณ์เดิม), จำนวนไฟล์แนบ, เปิดหนังสือถัดไป, ข้อเกษียณล่าสุด, ป้องกันคลิกบันทึกซ้ำ, แจ้งสถานะออนไลน์
- E1–E7: ตรวจทานก่อนส่ง, ค้นหารายชื่อครู, ข้อสั่งการล่าสุด, เตือนเอกสารซ้ำ, ประวัติแจ้งเตือน, ผู้รับ/สถานะรับทราบ, ลิงก์ตรงถึงเอกสาร
- PWA: ติดตั้งฟรีบนหน้าจอมือถือ, มีไอคอน/manifest/service worker, Badge บนอุปกรณ์ที่รองรับเมื่อเปิดแอป, ไม่ใช้บริการ Push แบบเสียเงิน
- เสียง: สร้างเสียงสั้นในเบราว์เซอร์ ไม่อ้าง URL ภายนอก ปรับ 0–100% และทดสอบได้
- ไม่เพิ่มกำหนดเส้นตายแยก, รายงานผลการทำงาน, ตรวจรับงาน, บริการเสียเงิน

## กฎสิทธิ์หัวหน้า
1. ผอ. ส่งถึงกลุ่มแล้ว **ทุกคนในกลุ่มยังเห็นเอกสาร** แม้หัวหน้ามอบหมายครูเฉพาะบางคน
2. หัวหน้ากลุ่มบริหารงานมอบหมายข้ามกลุ่มบริหารงานได้; หัวหน้ากลุ่มสาระมอบหมายได้เฉพาะในกลุ่มสาระตน
3. บุคคลที่ได้รับมอบหมายข้ามกลุ่มเห็นเอกสารได้ แต่ไม่ทำให้กลุ่มปลายทางทุกคนเห็นโดยอัตโนมัติ
4. การรับทราบหนังสือกับการรับทราบงานมอบหมายเก็บคนละรายการ ไม่ลบประวัติเดิม
5. เปลี่ยนหัวหน้าแล้ว **หัวหน้าคนใหม่** เห็นเอกสารเก่าของกลุ่มและดำเนินงานที่ค้างได้
6. การมอบหมายใหม่ต้องเก็บเหตุการณ์และ audit log โดยไม่แก้ทับข้อเกษียณเดิม

## ต้องตรวจรับก่อน Merge/Deploy
- [ ] ตรวจสอบ Firebase Security Rules ในโครงการจริง: บังคับสิทธิ์อ่าน/เขียนที่ฝั่งฐานข้อมูล โดยเฉพาะสิทธิ์หัวหน้า/การเกษียณ/รายชื่อผู้รับ (โค้ด UI อย่างเดียวไม่ใช่ระบบรักษาความปลอดภัย)
- [ ] สำรองข้อมูล Firestore และไฟล์ Drive จาก Production ก่อนเปลี่ยน
- [ ] ทดสอบ ผอ. หนังสือเข้า -> รองฯ -> ผอ. เลือก 1 กลุ่ม/หลายกลุ่ม/หลายครู -> ผู้รับรับทราบ
- [ ] ทดสอบหัวหน้ากลุ่มบริหารงานมอบหมายข้ามกลุ่ม และหัวหน้ากลุ่มสาระถูกปฏิเสธเมื่อข้ามหมวด
- [ ] ทดสอบหัวหน้ากดรับทราบโดยไม่มอบหมาย ครูเดิมยังเห็นหนังสือ
- [ ] ทดสอบเปลี่ยนผู้รับใหม่เมื่อผู้รับเก่าเคยรับทราบหนังสือแล้ว และการแจ้งเตือนงานใหม่
- [ ] ทดสอบเปลี่ยนหัวหน้าและผู้รักษาการในกลุ่มที่มีงานค้าง
- [ ] ตรวจการตั้งค่า PWA, ไอคอนและเสียงใน Safari iOS กับ Chrome Android
- [ ] ทดสอบเปิด PDF Google Drive ใน iframe กับบัญชีผู้ใช้ที่มีสิทธิ์ (หากไฟล์ห้ามฝัง ต้องใช้ปุ่มเปิดไฟล์)
- [ ] ตรวจการจัดการร่างข้อความในเครื่องส่วนตัวและเครื่องใช้ร่วมกัน (localStorage)
- [ ] ทดสอบมือถือ/แท็บเล็ตในหน้าทะเบียนและหน้าฟอร์ม
- [ ] ทดสอบ Firestore ขณะที่ผู้ใช้สองคนเกษียณเอกสารเดียวกันพร้อมกัน
- [ ] ยืนยันการออกเลขคำสั่ง/หนังสือออกและการลงนาม PDF ไม่ถดถอย

## สิ่งที่ไม่ทำ
- ไม่ส่ง Push ขณะเว็บปิดด้วย Cloud Functions หรือบริการชำระเงิน
- ไม่แสดงตัวเลข badge แบบเรียลไทม์ขณะปิดแอปทุกยี่ห้อ (ข้อจำกัดระบบปฏิบัติการ)
- ไม่แก้หรือโยกย้ายข้อมูลเก่าโดยอัตโนมัติ
- ไม่เก็บร่างไฟล์แนบไว้ใน localStorage (เก็บเฉพาะข้อมูลข้อความฟอร์ม)
