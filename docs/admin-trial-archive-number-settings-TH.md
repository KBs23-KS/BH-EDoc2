# BHS E-Document — การตั้งเลขถัดไป และจัดเก็บข้อมูลทดลอง (30 ต.ค. 2569)

## แอดมิน: ตั้งเลขถัดไป
เมนู ตั้งค่าระบบ → “กำหนดเลขหนังสือที่จะออกถัดไป” (คืนความสามารถเดิมจากไฟล์ 28 ต.ค. 2569)
- เลือก ORDER (เลขคำสั่งโรงเรียน) หรือ OUT (เลขหนังสือออก) และปี พ.ศ.
- อ่านตัวนับที่ออกไปแล้วและเลขสูงสุดในทะเบียน/เอกสาร รวมถึงเลขที่ยกเลิกและเลขทดลองที่ซ่อน
- ตั้งได้เฉพาะเลขใหม่ที่มากกว่าที่เคยออกไปแล้ว (นับเลขจาก counter และฐานข้อมูล)
- จัดเก็บใน Firestore transaction, ตรวจว่าตัวนับไม่ถูกเปลี่ยนระหว่างกดบันทึก, มี Audit Log
- การตั้งเลขถัดไป **ไม่ย้อนกลับเลขเดิมเป็น 1** และไม่แก้เลขที่อยู่ในเอกสาร

## แอดมิน: จัดเก็บ/ซ่อนรายการทดลองจำนวนมาก
เมนู เลขคำสั่งโรงเรียน → เลือก checkbox หลายแถว → “จัดเก็บ/ซ่อนรายการทดลองที่เลือก”
- เลือกได้ครั้งละไม่เกิน 50 รายการ ใน **หน้าที่แสดงอยู่** เท่านั้น
- เลือกได้เฉพาะเลขจองที่ยังไม่ยกเลิก หรือเลขที่เชื่อมกับ *คำสั่งร่าง* สถานะรอรองฯ/รอ ผอ./ส่งกลับแก้ไข และยังไม่ลงนาม/เผยแพร่/รับทราบ/เกษียณมอบหมาย
- กรณีเลขมีสถานะ “สร้างคำสั่งแล้ว” ระบบตรวจกลับไปยังเอกสารด้วย linkedDocumentId และ reservationId; หากไม่ตรงกันจะไม่อนุญาต
- บันทึกใน Firestore transaction ต่อรายการ: ติดธง trialArchived บนเลขคำสั่ง และ trialArchived + isDeleted บนเอกสารที่เชื่อม พร้อมประวัติและ Audit Log
- ไฟล์บน Drive ไม่ถูกลบ ข้อมูลเดิม/รหัสเลขเดิมไม่ถูกเปลี่ยน และ counter ไม่ถูกแก้
- ถ้าบางรายการมีปัญหา รายการนั้นจะไม่ถูกเปลี่ยน แต่รายการสำเร็จก่อนหน้ายังคงสำเร็จ; จะแจ้งผลรวม

## กู้คืน
เมนู เลขคำสั่งโรงเรียน → “รายการทดลองที่จัดเก็บ” → กู้คืนทีละรายการ
- กู้คืนเลขและเอกสารร่างที่เชื่อมแบบ transaction เดียว
- รายการทดลองที่จัดเก็บไม่แสดงในทะเบียนปกติ, ผลค้นหาทั้งระบบหรือรายงานส่งออก
- เอกสารร่างที่จัดเก็บไม่แสดงใน dashboard, งานรออนุมัติ, การแจ้งเตือน และผลค้นหา (อาศัย activeDocs)
- ถังขยะป้องกันการกู้คืน/ลบถาวรของเอกสารร่างประเภทนี้ เพื่อป้องกันเลขและเอกสารไม่ตรงกัน
- ข้อมูลที่จัดเก็บยังรวมอยู่ใน Backup/Restore ของแอดมิน

## ขอบเขตและข้อควรระวัง
- ไม่ใช่การลบถาวร และไม่ใช่การรีเซ็ตเลขเอกสาร
- ไม่มีการปรับเปลี่ยนระบบ Firebase Auth, Firestore Rules หรือ Google Drive
- ควรสำรองข้อมูลให้ครบก่อนทดลองล้างจริง และทดสอบกับข้อมูลตัวอย่าง
- สิทธิ์ในหน้าเว็บเป็นเพียง UI/logic client; ยังต้องเสริมการป้องกันด้วย Firestore Security Rules และการยืนยันตัวตนของแอดมินที่ปลอดภัยก่อนเปิดใช้ข้อมูลจริงเต็มรูปแบบ
